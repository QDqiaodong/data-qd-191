# 跨批对账契约（reconcile，报告格式版本 1）

离线工作站各自按本批 v1 标准换算合成色谱浓度。`peak-quant reconcile --sources DIR --plan PLAN --output REPORT` 把跨批净差对齐到同一虚拟对照件零点后交给下游记账。仅用 Python 3.11+ 标准库与自制合成数据，不接入外部服务、真实样本或仪器。

## 计划（PLAN）与源文件

PLAN 是不超过 8,000,000 字节的严格 UTF-8 JSON 对象（拒绝重复 JSON 键、`NaN/Infinity`），恰含字段：

- `batches`：批次 ID → 源文件 ID 的对象，2 至 12,000 个键；从 `DIR/<源文件ID>.json` 读取完整 v1 源文件。至多 256 个不同文件，总源字节（同一文件只计一次）不超过 64 MiB，单文件不超过 8 MiB。多个批次可共用同一合成底稿，但各自有独立零点。
- `anchor`：必须是 `batches` 的一个键；其每个所选分析物的修正量恒为 0。
- `analytes`：1 至 4 个不重复 v1 ID（自动按字典序规范化），必须在每个批次源中存在。
- `panels`：0 至 24,000 条对接板，每条恰含 `id,left,right`；板号唯一。`left`、`right` 各为 `[batch_id,run_id]`，两批次必须不同，且都指向 v1 **未知**运行。板可共享批次或运行，不要求一对批次只有一块板，也不允许用数值相等合并板号。
- `queries`：1 至 16 项，每项恰含 `id,analyte_id,left,right`；查询 ID 唯一，分析物必须取自计划，左右同样必须是未知运行（允许同批次）。净差方向恒为左减右。

所有 ID 走 v1 语法 `[A-Za-z0-9_:-]{1,64}`。重复键、缺失/多余字段、非法引用、类型错误或超出上限一律拒绝（退出 2，stderr 定位）。先对每个被引用源做**完整** v1 校验（包括对接与查询都用不到的记录），再在各批内对所选分析物按旧口径定量：固定窗口、精确带符号积分、等权带截距拟合、正斜率门槛。任一所选分析物在任一批不能拟合即整体输入计算失败，不借另一批曲线补齐。板与查询只用本地反推浓度（精确 `Fraction`），不用原始面积或显示舍入，不丢弃负值或外插结果。

## 整板取舍规则

统一浓度 = 本地浓度 + 该批该分析物的加性修正量；不重新拟合批内斜率。每块保留的板要求左右统一浓度**精确**相等，且所有批次都必须能沿保留板（边可逆向）连到 anchor。允许环与并行板；环上每条约束都参与判定，不因已有路径而忽略。

1. 全板同时成立（所有分析物、所有板残差为 0）且全体连通时，只承认“不剔板”一种情形，不再枚举删除。
2. 全板不连通 → `unreconcileable`，原因 `full_graph_disconnected`，不再尝试剔板。
3. 否则逐一考虑只剔除一个板号：剩余板必须对**所有**所选分析物同时成立，且仍把所有批次连到 anchor。符合条件的板号全部列入 `removable_panel_ids`；不允许按分析物换板号，不允许从坏输入挑子图结算，最多剔一块。
4. 没有共同单板修复 → `unreconcileable`，原因 `no_common_single_panel_repair`。有效输入但无法对账不是命令错误：退出 0，报告照常列出全部查询与本地读数。

## 报告字段

顶层（键名字典序序列化，所有数组按 ID 字典序规范化，因此语义相同的重排输入产生逐字节相同的报告）：

- `format_version`：1。
- `anchor`：锚点批次 ID。
- `analyte_ids`：字典序分析物列表。
- `status`：`all_panels_consistent` / `single_panel_repairable` / `unreconcileable`。
- `unreconcileable_reason`：仅无法对账时为 `full_graph_disconnected` 或 `no_common_single_panel_repair`，否则为 `null`。
- `removable_panel_ids`：仅可单板修复时非空，按字典序列出全部可行剔除板号。
- `queries`：每项含
  - `id,analyte_id,left,right`（原样引用，`left/right` 为 `[batch,run]`）；
  - `left_local_concentration`、`right_local_concentration`：约分整数/分数字符串，任何状态都给出；
  - `min_net_difference` / `max_net_difference`：在**同一可行情形内**统一左右读数后相减所得净差的精确最小/最大值；无法对账时为 `null`；
  - `min_witness_panel` / `max_witness_panel`：达到对应极值的剔除板号；平局取字典序最小板号；全板一致（唯一情形为不剔板）时两端均为 `null`；
  - `bookable_net_difference`：仅当最小与最大精确相等时给出该精确净差，否则为 `null`。见证板号不代表已确认坏板。

### 如何复核见证

对见证板号 p（全板一致时即“不剔板”）：取报告中该查询分析物在各批的本地浓度，沿任意一条不经过 p 的 anchor 路径用保留板的等式 `修正量[right] − 修正量[left] = 本地[left] − 本地[right]` 递推（anchor 修正量为 0），把得到的两批修正量分别加回左右本地浓度再相减，结果必须与对应极值字符串逐字符相等。报告不展开“候选板 × 批次”修正量表。

## 算法与确定性

每个分析物在同一张批次图上建一棵 DFS 生成树：树边确定以 anchor 为零的树解 `t`；每条非树边给出精确有向残差 `r = d − t[L] + t[R]`（`d = 本地R − 本地L`）。树上差分同时累计每条树边割集内坏/好残差计数、带符号和与平方和：割集只含坏边且 `b·Σr² = (Σ±r)²` 时该树边可剔，子树所需唯一平移量直接由带符号和除以计数得到；非树边仅当它是唯一坏边时可剔。各分析物候选集合的交集即共同单板修复。全部算术为精确 `fractions.Fraction`，判定、相等与极值均无浮点参与。

## 失败与发布边界

计划/源结构错误、引用错误、拟合失败或交付错误退出 2 并在 stderr 定位；报告只在全部计算成功后经临时文件加硬链接原子新建，拒绝覆盖已有目标或符号链接，失败不留下新报告。保留全部既有 CLI 与 Python 接口。月末 12,000 批大例由 `scripts/reconcile_month_end_demo.py` 生成并核对，且只给对账进程设 `RLIMIT_CPU=90`（生成 fixture 与读报告断言不计入，计算不挪到生成器或无配额子进程）。
