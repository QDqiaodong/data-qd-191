# 分片流装配契约（`peak-quant assemble`，v1 源文件交付）

本命令把归档程序留下的分片按清单（PLAN）声明的精确仿射对时关系重建成一份可直接交给既有 v1
定量入口（`peak-quant --source ... --output ...`）的源文件。全程只使用 Python 3.11+
标准库与自制合成数据，不接触真实物质、仪器、实验或网络。

```sh
peak-quant assemble --plan PLAN --output SOURCE < stream.jsonl
```

标准输入是一次性、不可 seek 的 UTF-8 JSON Lines 分片流；成功退出 0，任何输入、覆盖、冲突、
表示或文件错误退出 2，并在 stderr 标明错误类别及相关运行/分片。目标文件只在流读完且整批
约束全部通过后才原子新建，绝不覆盖已有文件或符号链接，失败不留新目标。

## PLAN（UTF-8 JSON，≤ 2,000,000 字节）

顶层恰有 `analytes`、`runs` 两个键，拒绝重复 JSON 键、未知或缺失字段。

- `analytes`：沿用 v1 规则（1–30 个唯一 ASCII id，`window=[lo,hi]`，0≤lo<hi，有界十进制字符串）。
- `runs`：1–200 个，沿用 v1 的 `id`、`kind`（standard/unknown）与浓度规则，但不含
  `samples`，改为：
  - `span`：绝对时间闭区间 `[lo,hi]`，非负且正宽，必须包含所有分析物窗口；
  - `fragments`：1–16 个分片，每个恰有 `id`、`anchors`；分片 id 在整批唯一。
- `anchors`：恰两个 `[局部时间, 绝对时间]` 对，两轴均非负且严格递增。两点定义该片自己的
  精确仿射对时关系；不从信号相似度反推，锚点也不是信号采样点。

## 分片流（JSON Lines，流 ≤ 320,000,000 字节，每行 ≤ 160,000 字节含换行）

- 每行恰含 `fragment_id` 与 `samples`；最后一行允许无换行，不允许空行。
- 每片 2–2,000 个 `[局部时间, 信号值]`，局部时间严格递增且位于两个局部锚点之间（可等于端点）。
- 清单中每片恰出现一次：未知引用、重复交付、漏交（读到流结尾仍缺片）一律拒绝；不承诺排序。
- 所有 id 与数值字符串沿用 v1 规则（id 为 1–64 位 `[A-Za-z0-9_:-]`；数值为最多 9 位整数、
  6 位小数的有界十进制字符串），解析为精确 `Fraction`。

## 入库判据（精确 Fraction 运算，无浮点）

对时后，每片按线性插值理解为只在其首末采样点之间有定义的曲线。只检查每条运行的 `span`：

1. 各片定义域的并集必须完整覆盖 `span`，不得跨空档插值；
2. 同一时刻有多片提供数据时，所有曲线在共有部分必须精确相等——包括仅在一点相接的情形；
   重叠区间仅两端相同而中间不同仍判冲突，不用首到/末到/均值裁决。
3. 区间外的值不参与比较，但区间外分片仍须通过全部输入校验。

## 输出（仅含 v1 字段的源文件，≤ 8,000,000 字节）

- 每条运行取 `span` 两端及区间内部全部真实斜率转折点作为 `samples`；共线采样点与分片边界
  不留点；端点若无采样则取精确插值。每运行 2–2,000 点。
- 对时、比较、去共线全部精确；只有最终必须输出的点才检查 v1 十进制可表示性（分母整除
  10⁶、整数部分 ≤ 999,999,999），不舍入；中间共线点即使不可写成 v1 数字也不拒收。
- 输出经 `json.dumps(sort_keys=True, indent=2)` 规范化：等价对象键顺序、分片声明顺序与分片
  到达顺序都不改变输出字节；运行次序保留 PLAN 次序。
- 标准品浓度、分析物窗口等 PLAN 元数据按规范化文本写入；结构与既有 v1 校验完全兼容。

## 错误类别（stderr 前缀）

| 类别 | 触发情形 |
| --- | --- |
| `assemble plan input` | PLAN 结构、字段、引用、锚点或元数据非法 |
| `assemble stream input` | 行超长/空行/坏 JSON、未知或重复分片、采样非法、流结尾缺片 |
| `assemble coverage` | 某时刻无片覆盖或相邻事件间存在空档 |
| `assemble conflict` | 重叠曲线在共有部分（含单点相接）不精确相等 |
| `assemble representation` | 最终输出点不可表示为 v1 十进制，或样本数/字节数超限 |
| `error: ...`（OSError 等） | 目标已存在/符号链接、临时空间或其他文件错误 |

## 小样例（fixtures/assemble/）

`plan.json` + `stream.jsonl` 是文档首条手工算例：未知运行 `u1` 的区间 [0,2] 由左片
（锚点 (0,0)/(3,1)，采样 (0,0),(1,1),(3,3)）与右片（锚点 (0,1)/(3,2)，采样
(0,3),(1,2),(2,1),(3,0)）拼成。装配结果恰为 `(0,0),(1,3),(2,0)`，含 1/3 等中间时刻也不会被
拒收。配合浓度 0/2、面积 0/6 的两条标准，旧定量入口给出面积 3、浓度 1：

```sh
peak-quant assemble --plan fixtures/assemble/plan.json \
  --output run/assembled.json < fixtures/assemble/stream.jsonl
peak-quant --source run/assembled.json --output run/quant.json
```

## 大规模管道实跑（scripts/assemble_pipeline_demo.py）

200 条运行 × 8 片 × 1,024 采样，生成器按片序号轮转发送，任何运行在最后一轮前都不完整；
消费进程（且仅消费进程）设置 `RLIMIT_AS=192 MiB`。合成分片互相重叠，每条运行最后只剩
2–4 个点，驱动程序用独立 oracle 逐点核对全部 200 条运行，而不只看退出码：

```sh
python scripts/assemble_pipeline_demo.py --workdir run/pipeline
# 缩小规模：--runs 12；改变内存上限：--mem-mib 192
```

本环境实测：流约 33.7 MB，消费进程峰值 RSS 约 22 MiB，整轮约 80 秒，全部 200 条逐点通过；
归档体量由流字节与片数衡量，不能用最终文件（约 50 KB）估算。
