# 合成合计披露的离线审查 v4

v1（`docs/contract.md`）回答固定窗口的未知样浓度，v2（`docs/release-contract.md`）做逐版质量签发，v3（`docs/explain-contract.md`）导出候选峰解释包并支持离线联查；v4 在**同一份固定的自制合成快照**上增加对外合计的可复核披露审查。接收方持有历次已发合计及其覆盖记录，因此单看本次某行的成员数不能判断明细是否仍受保护。本模块只使用精确有理数、Python 3.11+ 标准库与人工合成数据，不接触真实物质、仪器、实验、网络或攻击场景。

审查口径刻意简化且完全显式：对接收方而言，每个明细值都是一个**独立的有理数未知量**；一条合计行是一个等式（各成员等权相加等于公开总值），成员关系公开。模型不引入真实值、非负性、标准浓度范围、其他数据源或分析物之间的任何假设。某受保护单元在与全部已发等式一致的所有有理数赋值中只能取同一个值时，即视为被**确定**。

## 命令

- 生成：`peak-quant disclosure --source SOURCE --plan PLAN --output BUNDLE`
- 离线复核：`peak-quant disclosure-check --plan PLAN --public PUBLIC --audit AUDIT`
- v1 扁平入口、v2 `release`/`release-show`、v3 `explain`/`contrast` 以及 `assemble`、`benchmark` 的行为完全不变。
- Python 入口：`peak_quant.disclosure.disclosure(...)`、`peak_quant.disclosure.disclosure_check(...)`、`peak_quant.disclosure.verify_disclosure(plan, public, audit)`。

成功退出 0；非法输入、无效证明、结构或文件错误退出 2，定位信息写 stderr。所有算术为精确 `fractions.Fraction`，输出均为约分整数或分数字符串，全程不使用浮点。

## SOURCE 与数值口径

SOURCE 必须是合法 v1 源文件（8,000,000 字节上限与全部 v1 校验不变）。生成端沿用 v1 的固定保留时间窗口、全批等权含截距最小二乘标准拟合与 `浓度 = (面积 − intercept) / slope` 反推口径：不截断负值、不外插修正；任一分析物拟合失败或源数据校验失败则整体不交付。每个统计单元由「未知运行 ID、分析物 ID」唯一确定，取值是 `quantified` 中的精确浓度——不是标准浓度、积分面积或质控签发记录。历史与本次都针对这一份固定快照，不处理换源与更正。

## PLAN 契约

严格 UTF-8 JSON，不超过 2,000,000 字节，拒绝重复 JSON 键、`NaN`/`Infinity` 常量、额外或缺失字段。顶层恰含三个键：

| 键 | 规则 |
| --- | --- |
| `protected` | 非空、无重复的 `[run_id, analyte_id]` 对数组；同一运行可只保护一个分析物 |
| `published` | 0..512 行历史已公开清单；顺序可任意（不参与业务优先级） |
| `requests` | 1..512 行本次请求；**数组顺序就是业务优先级，不可重排** |

每行恰含 `id`、`analyte_id`、`members`；历史行另含 `total`。规则：

- ID 沿用 v1 语法 `[A-Za-z0-9_:-]{1,64}`；合计行 ID 在两份清单的并集中唯一。
- `members` 是非空、无重复的未知运行 ID 数组（至多 200 个），表示同一分析物各成员等权相加；禁止混合不同分析物，禁止引用标准运行或源中不存在的运行/分析物。
- 历史 `total` 必须是约分整数或分数字符串，并与固定快照按成员求出的实际合计**精确**相等，否则退出 2。
- 合法的排序变化包括历史数组、保护清单、成员顺序与对象键顺序；`requests` 的顺序变化会改变决定与输出。

### 精确有理数字符串的语法与大小检查

输入的历史 `total`、产物中的总值、证明系数与变化量都使用同一套精确文本语法：可选负号 + 十进制整数，可选地再接 `/` 与正整数分母（如 `0`、`-3`、`5/3`、`-7/9`）。规则：

- 不接受 JSON 数字、小数、指数写法；分母必须为正且不允许前导零；
- 必须是**约分**表示，`2/2`、`0/3`、`-0` 这类未约分拼法直接拒绝；
- 分子、分母各不超过 40 位十进制数字，整串不超过 128 个字符。

## 审查决定（按优先级逐行）

历史行先进入等式集合。若历史等式本身已经确定任一受保护单元，**整次生成失败**——不能靠本次扣留宣称补救成功。随后按 `requests` 原顺序逐行试发：把该行与历史及本次此前**实际发出**的行合并考虑；若会确定任一受保护单元则扣留，否则必须发出并把其等式计入后续判断。这不是全局挑选最多行的问题，也不是每行只与历史比较一次；扣留不是文件错误，但被扣留行的等式与总值都不能作为后续行的已发事实。成员列表相同但 ID 不同的安全冗余行可以发出。决定只取决于哪些单元被保护与公开的成员关系，不取决于合计是否恰好抵消为零。

实现上对每个分析物维护增量有理高斯-若尔当消元（RREF），列宇宙在开始前就登记全部受保护单元与全部行成员：一个单元被确定，当且仅当它不出现在该等式系统的任何零空间方向中。每次试发在引擎克隆上精确模拟，使用与最终审计相同的判定谓词，而非近似推断。

## BUNDLE 与两份产物

`BUNDLE` 是一个新本地目录，同一目标只由一个进程写入。目录先在同级隐藏暂存目录中构建，两份文件都持久化后再一次性改名到位；因此外部永远看不到只含一份产物的 BUNDLE，第二份文件写入失败时不会留下可被当作成功的目录或暂存残骸，已存在的目标（含符号链接）绝不被覆盖或改动。下游只接收 `public.json`，整个目录不得转发。

### `public.json`（对外，格式版本 1）

顶层恰含 `format_version` 与 `issued`。`issued` 仅包含本次实际发出的行，按原优先级排列，每行恰含 `id`、`analyte_id`、`members`（成员按字典序规范化输出）与精确 `total`。全扣留是成功结果，`issued` 为空数组。文件中绝不夹带历史合计、扣留行、保护清单、明细值、原始轨迹、证明或源指纹。

### `audit.json`（仅内部流转，格式版本 1）

顶层恰含 `format_version`、`requests`、`freedom_proofs`；不保存原始轨迹、拟合细节或任何扣留行的合计值。

- `requests` 与 PLAN 请求一一对应且同序，每项含 `id`、`decision`（`issued`/`withheld`）与 `withholding_proof`（发出行为 `null`）。
- 每条扣留行的证明：给出受保护单元 `protected_unit` 与非零 `combination`（每项为 `row_id` + 非零 `coefficient`）。该组合只允许引用历史行、此前实际发出的行以及**本行自身**（本行必须参与），其成员系数之和恰为该受保护单元的单位向量。证明不需要算出该单元的值。
- `freedom_proofs` 为每个受保护单元给出一份最终已发集合的变化证明：`protected_unit` 与非空 `changes`（每项 `unit` + 非零 `change`）。目标单元的变化量非零，且对每一条历史与已发行，其成员变化量之和恰为零，即可以改变该明细而不改变任何已发等式。证明单元只能取自 PLAN 中出现过的单元；变化量是有理数见证，不是明细值，也不允许照抄真实明细。该证明针对最终（最大）等式集合成立，因而自动覆盖它的每个更短已发前缀。多个受保护单元可以引用等价的变化方向。

## 离线复核的边界（`disclosure-check`）

复核人信任自己持有的 PLAN，但**不信任两份产物**；复核目录不需要 SOURCE、运行缓存或任何拟合进程。复核器独立完成：

1. 版本与结构：两份文件的顶层字段集合、格式版本、每项字段集合与类型；
2. 行与成员对应：公开行的分析物、成员集合与 PLAN 完全一致，公开行恰为 audit 标为发出的请求且顺序正确，发出/扣留位置与 PLAN 优先级一一对齐；
3. 扣留证明：在每个扣留位置只允许引用真实的历史/已发前缀及该行，逐系数重算线性组合并验证其恰为所声明受保护单元的单位向量，且本行确实参与；
4. 变化证明：逐单元验证变化量非零、引用单元均在 PLAN 中出现、且对每条历史与已发行的成员变化量之和恰为零；每个受保护单元恰有一份证明。

仅“存在一份证明”或相信产物里的标签不构成通过。复核成功只说明**披露决定与证明**和 PLAN 一致；无源模式下公开 `total` 只做精确数值格式检查，不宣称复算它们确实来自原始数据。证明表示可由生成端自由选择，复核器独立核等式，不要求重新运行决定生成或拟合。

## 确定性

同一语义输入重复生成，两份文件都逐字节一致（键排序、双空格缩进、末尾换行的规范 JSON）；历史数组、保护清单、成员与对象键的合法重排不影响输出；只有业务优先级（`requests` 顺序）变化才允许改变结果。证明存在多解时，生成器按固定规则选取（受保护单元按字典序、RREF 零空间的规范基向量、组合按行 ID 排序）。

## 可直接运行的离线合成例子

曲线为「面积＝3×浓度」，未知运行 X、Y、Z、W 的单分析物浓度依次为 1/3、2/3、4/3、5/3，只保护 X：

```sh
peak-quant disclosure --source fixtures/disclosure/input.json \
  --plan fixtures/disclosure/plan.json --output run/disclosure-main
peak-quant disclosure-check --plan fixtures/disclosure/plan.json \
  --public run/disclosure-main/public.json \
  --audit run/disclosure-main/audit.json
# 只复制 plan.json、public.json、audit.json 到没有 SOURCE 的干净目录后仍可复核
```

主 PLAN（历史 H=X+Y；请求 B=X+Z、C=Y+Z、D=Y+Z+W）发出 B=5/3 与 D=11/3、扣留 C；C 的扣留证明是 (H+B−C)/2 恰为 X 的单位向量，而 D 若错把 C 当已发事实，就会继承一个已失去保护的前缀。配套 PLAN 还演示：追加同成员的 E 仍被扣留；交换 B、C 优先级后 C 发出、B 扣留而 D 仍可发；历史 H 改为 Y+W（总值 7/3）后 B、C 都发出而 D 扣留；H、B、C 全部进入历史时 X 已无补救、生成失败；伪造历史总值、单请求全扣留、同一运行另一分析物独立发布；以及含负值/外推值的合计（N=−1 同时为 negative 与 extrapolated）原样进入合计而非被过滤成小计。
